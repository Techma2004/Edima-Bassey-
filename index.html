01 · about

I learn by building complete systems, not by reading about them. That's shaped everything from a school management portal used by real students and teachers, to a private messaging platform built from a single Flask file, to an AI assistant I'm currently growing into something closer to a real operating layer than an app.

I care about software that runs where the infrastructure is imperfect — patchy power, patchy networks, budget hardware. That's not a constraint I work around, it's a design principle: local execution, offline capability, and lightweight footprints come first, cloud dependence comes second.

Recently graduated and now working independently across the stack — backend, frontend, systems, and increasingly security. Currently deep in cybersecurity self-study alongside active project work.

03 · projects

Selected work

Building 2025 — present
Sally Station

A JARVIS-style local AI assistant designed to run entirely offline: a PC-based "Station OS" paired with an Android companion app, aiming for a synced "JARVIS MODE" across both. Currently building the macro/protocol system and mood state machine that downstream features — avatar expression, voice tone — depend on.

Django + Channels llama.cpp / Qwen2.5-Coder whisper.cpp PyQt6 + GLSL
Deployed 2024 — 2025
NNSS Calabar

A multi-role school management portal built for a naval secondary school — five user roles, six arms, WAEC grading, and a five-component score structure. Rebuilt on PocketBase for the final version and handed off to the school's Cisco teacher for institutional use.

PocketBase Node.js (v1) Role-based access
Prototype 2023 — 2024
WENET

A private WhatsApp/Telegram-style messaging platform, built as a single-file Flask app with real-time messaging, contact discovery via phone matching and QR codes, and message-request flows. An earlier build explored a "WENET Pay" peer-to-peer payments concept and an admin panel with RBAC and AI moderation.

Flask Real-time messaging RBAC
Active 2024
Cross-platform browser shell

A lightweight Rust/Dioxus browser using the system webview (wry) to target both desktop and Android from one codebase — tab management, URL normalization, and DuckDuckGo fallback routing.

Rust Dioxus wry
